Sortie errors and fixes (for agents)#

A command error is a sortie::Error with a stable code and the Rust call site that built the command:

error[sortie::gone]: `push_task` on group "Red CAP 1": Unit doesn't exist (at logic/src/lib.rs:48:9)

e.report() is the long form the runtime logs: the call site, the Lua traceback, the session and command ids and a help: line. e.code(), e.origin(), e.lua_traceback(), e.failure() (op, target, message) give the parts; e.is_session_ended() tells the normal end of a session from a failure.

Handling errors in a mission#

let sam = match ctx.group(groups::SAM_NORTH) {
    Ok(g) => g,
    // In the manifest, but no live unit now (late activation, already destroyed).
    Err(sortie::Error::NotInWorld { .. }) => return Ok(()),
    // UnknownSymbol: the running mission was built from another scenario lock.
    Err(e) => return Err(e),
};
match sam.set_option(Alarm::Red).key("sam-hot").await {
    Ok(()) => {}
    // The group died between the check and the command: expected in a live mission.
    Err(sortie::Error::Gone(f)) => eprintln!("SAM North is gone: {}", f.message),
    // The session ended while the command was in flight: not a logic error.
    Err(e) if e.is_session_ended() => return Ok(()),
    // Anything else: the runtime records it with `e.report()` (code, call site, hint).
    Err(e) => return Err(e),
}

An Err that leaves the mission function or a task spawned with ctx.spawn is recorded as a logic error (stderr of the logic, with its call site) and ends that task only. SessionEnded is never recorded. A panic is recorded the same way, with its location. Nothing runs the mission function again until the next session or a restart of the logic, so the work after the failed command never happens: do not end the mission function on one optional command (an AI option, a message, smoke). Give it a key, retry it once on Timeout, log the rest:

let alarm = || sam.set_option(Alarm::Red).key("sam-north-red");
let mut done = alarm().await;
if let Err(sortie::Error::Timeout(_)) = &done {
    // The same key: a first try that reached DCS after all does not run twice.
    done = alarm().await;
}
if let Err(e) = done {
    // Optional: note it and go on instead of ending the mission function.
    eprintln!("SAM North stays as it was: {}", e.report());
}

Limits (engine 0.4.0)#

A refusal by one of the engine's limits is told by data, never by its text: e.limit() -> Option<&sortie::Limit> (kind: LimitKind, budget, writer, capacity, per_second, needed, available), e.retry_after() -> Option<Duration>, e.is_limit(). The code and e.capability() are what 0.3.0 gave; against a 0.3.0 engine both are None. The SDK never retries by itself.

let mut tries = 0;
let fuel = loop {
    match ctx.dcs().unit(UnitSel::name("SAM North-1")).fuel().await {
        Ok(f) => break Some(f),
        // A rate or DCS-time budget: the engine names the wait of this same read.
        Err(e) if tries < 3 && e.retry_after().is_some() => {
            tries += 1;
            ctx.sleep(e.retry_after().unwrap_or_default()).await;
        }
        // A forbid (not in the catalog, switched off): waiting never helps.
        Err(e) if e.is_forbidden() => break None,
        Err(e) => return Err(e),
    }
};

  • retry_after() is the wait of the same command sent again unchanged, from the refusal, if the logic sends nothing else meanwhile: after a 256-read batch from a full bucket (200 - 256 = -56) another 256-read batch waits 1.28 s, a single read 0.285 s. When several budgets refuse, the limit is the one with the longest wait. None for sizes, caps and waits, and for a heavy call refused while the logic's previous heavy call is not back (one heavy call of a writer at a time: do not join! two).
  • A batch refused at the limit check ran no call (the engine checks it whole before sending).
  • e.is_forbidden(): Rejected with a capability and no limit (a path not in the catalog, off by default or switched off by the owner, an operation disabled in engine.toml).
  • ctx.sleep follows the ticks, so a wait can end a little early: the next refusal names the rest, which the loop above survives.
