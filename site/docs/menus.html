Деревья меню F10#

ctx.menus() строит меню радио F10: пункты и подменю для всех, для одной коалиции или для одной группы. Каждое дерево — именованный ресурс сессии, как рисунок на карте: движок помнит его, показывает в реплике мира (ctx.world().resources()) и убирает, когда сессия кончается. Повторная команда с тем же именем не ставит второе меню, а приводит существующее к новому описанию.

Команды меню из сценария (ctx.menu(коалиция), страница Логика на Rust) работают как прежде.

Ревизия API#

Деревья меню — API ревизии 1. Нажатие пункта дерева — событие ревизии 1: логика без event_rev = 1 его не получает.

#[sortie::mission(api_rev = 1, event_rev = 1)] // деревья меню — API ревизии 1, нажатия — событий 1
pub async fn with_menus(ctx: Ctx<MyMission>, _start: Start) -> sortie::Result<()> {
    let support = ctx
        .menus()
        .tree("support")
        .to(Coalition::Blue)
        .under(["Поддержка"])
        .command("sitrep", "Обстановка")
        .submenu("Дым", |s| {
            s.command_arg("smoke-red", "Красный", "red").command_arg(
                "smoke-green",
                "Зелёный",
                "green",
            )
        })
        .await?;
    let mut presses = support.presses();
    while let Some(p) = presses.next().await {
        if p.item.starts_with("smoke-") {
            let color = if p.arg == "red" {
                SmokeColor::Red
            } else {
                SmokeColor::Green
            };
            ctx.smoke(zones::TARGET.center(), color).await?;
        }
    }
    ctx.end_session(Outcome::Draw).await
}

Построение#

МетодЧто делает
tree(имя)новое дерево; без .to(..) его видят все
.to(кто)Audience::all(), коалиция (Coalition::Blue) или группа (Audience::group(..))
.under([..])подменю от корня F10, в которых висит дерево; общие с другими меню той же аудитории
.command(id, надпись)пункт; id вернётся в нажатии (TreePress.item)
.command_arg(id, надпись, arg)пункт со своей строкой (до 256 байт), она вернётся в TreePress.arg
.manifest_command(id, menus::X)пункт с надписью команды из сценария
.submenu(надпись, |s| ..)подменю; внутри те же command, command_arg, submenu
.overflow(Overflow::Reject)уровень длиннее 10 пунктов — отказ вместо листания (по умолчанию Overflow::Page)
.ttl(время)срок жизни; потом ResourceEnded с причиной EXPIRED

Ограничения (иначе Error::Invalid и ничего не меняется):

  • на одном уровне нет двух пунктов с одной надписью: DCS находит пункт по пути из надписей;
  • на уровне, который листается (см. ниже), нет пункта с надписью его страниц: More..., а на корневом уровне дерева ещё и More... (<имя дерева>);
  • не больше 200 узлов в дереве (страницы «More...» не считаются), у каждого пункта есть id, id в дереве не повторяются;
  • аудитория — все, коалиция или группа; страна, юнит и игрок — нет.

Длинные уровни: страницы «More...»#

DCS показывает на одном уровне меню не больше 10 пунктов. Уровень дерева длиннее 10 пунктов по умолчанию листается (Overflow::Page): DCS показывает первые 9 пунктов и подменю More..., в нём остальные, и так дальше — на странице снова 9 пунктов и More..., пока осталось больше 10 (уровень из 25 пунктов: 9, потом 9 и More..., потом 7). Листаются только уровни самого дерева, но не общие подменю under и не команды меню из сценария.

  • Страница корневого уровня дерева называется More... (<имя дерева>), например More... (targets). Корневой уровень (корень F10 или последнее подменю under) дерево делит с другими деревьями и командами меню из сценария, а DCS находит пункт по пути из надписей: с одной надписью More... на двоих пункты второго дерева попали бы на страницу первого. Надпись зависит только от имени дерева и не меняется, пока дерево живёт. Страницы внутри этой страницы и страницы в подменю самого дерева называются просто More...: на этих уровнях других деревьев нет.
  • Страница — не пункт: её нельзя нажать, в нажатии её нет. Нажатие пункта на странице несёт его собственные item, arg и ident, как на первой странице.
  • Страницы — тоже вызовы DCS (dcs_calls), но не узлы: в дереве из 200 узлов их не больше 22.
  • Изменение считается по тому, как пункты разложены по страницам: вставка в начало уровня из 14 пунктов ставит заново первую страницу и страницу с остальными (26 вызовов DCS), смена надписи на второй странице трогает только вторую страницу, а когда пунктов снова 10 или меньше, страница уходит одним вызовом.
  • .overflow(Overflow::Reject) — прежнее поведение: больше 10 пунктов на уровне — Error::Invalid, в DCS ничего не меняется.
// 14 целей на корневом уровне дерева: DCS покажет 9 и «More... (targets)», а в нём
// остальные 5.
let targets = (1..=14).fold(
    ctx.menus()
        .tree("targets")
        .to(Coalition::Blue)
        .under(["Цели"]),
    |t, i| t.command_arg(&format!("target-{i}"), &format!("Цель {i}"), &i.to_string()),
);
let m = targets.await?;
assert_eq!((m.change, m.dcs_calls), (Change::Created, 15)); // 14 пунктов и 1 страница
let mut presses = m.presses();
if let Some(p) = presses.next().await {
    // Нажатие «Цель 12» на странице несёт её id и arg: "target-12", "12".
    ctx.report().set("target", &p.item);
}
// Без листания: больше 10 пунктов на уровне — Error::Invalid, ничего не меняется.
let strict = (1..=11).fold(
    ctx.menus().tree("strict").overflow(Overflow::Reject),
    |t, i| t.command(&format!("s-{i}"), &format!("Пункт {i}")),
);
assert!(matches!(strict.await, Err(sortie::Error::Invalid(_))));

Меню одной группы#

DCS знает меню группы только по её id (Group:getID()), а id есть, только пока в группе сидит игрок. Поэтому дерево для группы, заданной именем или символом сценария, следует за слотом:

  • в группе никого нет — команда принята, дерево приостановлено (is_suspended(), фаза SUSPENDED, предупреждение в warnings, вызовов DCS ноль);
  • игрок занял слот — движок сам ставит меню для id группы;
  • игрок вышел — движок убирает меню, дерево снова приостановлено;
  • следующий игрок (в том числе в динамический слот с новым id группы) получает меню заново.

Нажатие такого пункта несёт группу (TreePress.group), ответить можно только ей. Дерево для группы, заданной Eid, живёт одну жизнь группы: когда группа погибла или заменена новой с тем же именем, приходит ResourceEnded с причиной SOURCE_GONE.

let jtac = ctx
    .menus()
    .tree("jtac/blue-1")
    .to(Audience::group(GroupSel::name("Blue 1")))
    .under(["JTAC"])
    .command("check-in", "Прибыл в район")
    .manifest_command("smoke", menus::SMOKE_TARGET) // надпись из сценария
    .await?;
if jtac.is_suspended() {
    // В группе пока нет игрока: меню появится, когда игрок займёт слот.
    ctx.report().set("jtac", "waiting");
}
ctx.spawn(async move |ctx| {
    let mut presses = jtac.presses();
    while let Some(p) = presses.next().await {
        if let Some(group) = p.group {
            ctx.message(group)
                .text(format!("Принято: {}", p.item))
                .await?;
        }
    }
    Ok(())
});

Нажатия копятся с момента, когда движок подтвердил дерево; ctx.menus().presses(имя) читает нажатия дерева, поставленного раньше или другой логикой.

Изменения#

DCS не умеет переименовать пункт меню, поэтому движок сравнивает новое дерево с поставленным и трогает только то, что изменилось:

Результат (MenuTree.change)КогдаВызовы DCS
Createdимени ещё нетпо одному на пункт и подменю
Unchangedдерево то жени одного
Updatedизменились пункты; или только ttlудалённые пункты, изменённый пункт и пункты после него на его уровне (так порядок остаётся заданным)
Replacedдругая аудитория или underвсё дерево заново
let tree = |extra: bool| {
    let t = ctx
        .menus()
        .tree("support")
        .to(Coalition::Blue)
        .command("sitrep", "Обстановка");
    if extra {
        t.command("tanker", "Где заправщик?")
    } else {
        t
    }
};
let m = tree(false).await?;
assert_eq!(m.change, Change::Created);
let m = tree(false).await?; // то же дерево: в DCS ничего не уходит
assert_eq!((m.change, m.dcs_calls), (Change::Unchanged, 0));
let m = tree(true).await?; // добавлен пункт в конце: один вызов DCS
assert_eq!((m.change, m.dcs_calls), (Change::Updated, 1));
ctx.menus().remove("support").await?;

Команды над одним именем выполняются в порядке отправки. .key(..) не нужен: повтор команды — та же команда. remove(имя) убирает дерево (нет такого — Change::Absent), remove_prefix("jtac/") — все свои деревья с этим началом имени, clear() — все свои меню.

Ограничения#

  • Что DCS делает с меню группы, когда игрок выходит, садится в другой слот или в динамический слот, на сервере 2.9.31 ещё не проверено (проверки PLY-LC1, PLY-LC3, PLY-LC23); Sortie убирает меню сам и ставит его заново.
  • Порядок пунктов из разных меню на одном общем уровне и поведение при открытом меню у клиента ещё не измерены (PLY-LC2, PLY-LC22). Страницы «More...» на сервере 2.9.31 ещё не проверены (PLY-LC22): как глубоко DCS вкладывает подменю и что она делает с 11-м пунктом уровня.
  • Команды меню из сценария (ctx.menu(..)) с 0.2.0 тоже регистрируются: в реплике мира они видны как дерево из одного пункта с именем sortie:menu/.., убираются при конце сессии (если в сессии была команда ревизии API 1 или новее; сессия только логик 0.1.0 оставляет их, как 0.1.0), а копия команды .per_group() в группе снимается, когда слот группы пустеет, и ставится заново следующему игроку.
