Объекты: статики, уничтожение, мусор#

Операции ревизии API 1 работают с объектами мира, у которых нет шаблона в сценарии: ctx.spawn_static ставит статический объект, груз или FARP, ctx.destroy убирает любой юнит, статик, груз, оружие в полёте или катапультировавшегося пилота, ctx.remove_junk чистит обломки и воронки, ctx.spawn_batch ставит много групп и статиков одной командой. Это типизированные операции, а не вызовы DCS: движок сам следит за именем, скоростью спавна и сразу сообщает миру, что изменилось.

Статики#

#[sortie::mission(api_rev = 1)] // статики, destroy и remove_junk — API ревизии 1
pub async fn statics(ctx: Ctx<MyMission>, _start: Start) -> sortie::Result<()> {
    let p = zones::TARGET.center(); // MapPoint
    // Категорию и модель DCS движок берёт из своей таблицы типов.
    let depot = ctx
        .spawn_static(".Ammunition depot", "USA")
        .named("Depot North")
        .at(p, 0.0)
        .key("depot-north")
        .await?;
    // Статик уже в реплике мира; DCS не шлёт BIRTH для статиков, событие Birth делает движок.
    let alive = ctx.world().entity(depot.eid).is_some_and(|e| e.is_alive());
    // Рабочий FARP — аэродром с позывным и частотой.
    let farp = ctx
        .spawn_static("FARP", "USA")
        .named("FARP North")
        .at(p.toward(90.0_f64.to_radians(), m(500)), 0.0)
        .heliport(
            Heliport::new()
                .callsign("London")
                .frequency_hz(127_500_000.0),
        )
        .key("farp-north")
        .await?;
    // Груз, который может поднять вертолёт; имя по умолчанию — `ammo_cargo#<сессия>-<n>`.
    let crate_ = ctx
        .spawn_static("ammo_cargo", "USA")
        .cargo(800.0, true)
        .at(p.toward(0.0, m(50)), 0.0)
        .key("crate-1")
        .await?;
    ctx.report().set("farp_airbase", farp.airbase.is_some());
    ctx.report().set("crate", crate_.name);
    let _ = alive;
    ctx.end_session(Outcome::Draw).await
}
  • Тип — имя типа DCS ("Cafe", ".Command Center", "ammo_cargo", "FARP", "Mi-8MT"), страна — ключ DCS ("USA", "RUSSIA"); коалиция следует за страной.
  • У статика DCS должна быть верная пара «категория — модель», иначе его не видно. Движок берёт её по умолчанию из своей таблицы (типы pydcs 1.0.0: укрепления, грузы, склады, FARP, самолёты, вертолёты, корабли и техника как статики); заданные .category(..) и .shape(..) важнее таблицы. Знает ли DCS тип, решает сам DCS (getDescByName на запущенной сборке): неизвестный тип — Error::Invalid. Для типа, которого в таблице нет (мод, новая сборка DCS), задайте и .category(..), и .shape(..); без одного из них — Error::Invalid с именем недостающего поля (для самолётов, вертолётов, кораблей и техники модель не нужна).
  • .on_unit(корабль, вперёд_м, вправо_м, угол) ставит статик на палубу корабля, он движется вместе с ним. .dead() — обломки, .hidden() — не виден на карте F10, .score(n) — очки за уничтожение, .livery(..), .raw(таблица) — дополнительные ключи таблицы DCS (ключ, который задаёт метод билдера, отклоняется; код Lua, имена файлов и NaN тоже — проверка сырых таблиц).
  • FARP, площадка и невидимый FARP ("FARP", "SINGLE_HELIPAD", "Invisible FARP") ставятся только с .heliport(..): так DCS делает из них аэродром. SpawnedStatic::airbase — его Eid, в мире у него host — статик. Позывной по умолчанию — первый ещё не выданный в этой сессии, частота по умолчанию 127,5 МГц AM.
  • Статики идут через тот же ограничитель скорости спавна, что и группы (по умолчанию 2 в секунду), полосой BULK. В sortie dev спавн без .key(..) отклоняется.

Имя — личность#

Имя статика уникально среди юнитов и статиков: DCS молча уничтожает живой объект с тем же именем. Поэтому движок по умолчанию отвечает Error::NameConflict, а .on_conflict(..) выбирает другое:

// Имя — личность статика. Повтор после перезапуска логики:
let depot = ctx
    .spawn_static(".Ammunition depot", "USA")
    .named("Depot North")
    .at(p, 0.0)
    .on_conflict(OnConflict::Keep) // живой статик того же типа — он и есть результат
    .key("depot-north-again")
    .await?;
if depot.kept {
    // ничего не создано
}
// Заменить живой статик новым (игрок в статике не сидит):
ctx.spawn_static(".Command Center", "USA")
    .named("Depot North")
    .at(p, 0.0)
    .on_conflict(OnConflict::Replace) // старый получает UnitGone с причиной Replaced
    .key("depot-north-hq")
    .await?;

Replace сначала проверяет всё, потом уничтожает старый статик и ставит новый на следующем кадре DCS. Юнит с этим именем не заменяется: Error::NameConflict. Перед постановкой слой Lua ещё раз смотрит на имя: если DCS не убрал старый статик (так, по сообщениям, бывает с FARP; не измерено), команда отвечает Error::Lua («DCS did not remove …»), новый статик не ставится, а старый остаётся в мире живым.

Keep для живого FARP возвращает и его аэродром в SpawnedStatic::airbase, как при первой постановке: после перезапуска логики повтор спавна снова даёт Eid аэродрома.

Уничтожение и мусор#

ctx.destroy(Obj::static_object("Depot North"))
    .key("depot-north-gone")
    .await?;
// Юнит с игроком не уничтожается без .allow_player(): у клиентов остаются «призраки».
match ctx.destroy(Obj::unit("Viper 1-1")).key("viper-gone").await {
    Ok(()) | Err(Error::Gone(_)) => {}
    Err(Error::Rejected(_)) => ctx.report().set("viper", "occupied by a player"),
    Err(e) => return Err(e),
}
// Обломки, воронки и мусор в объёмах DCS; результат — что насчитала DCS.
let center = zones::TARGET.center();
let junk = ctx
    .remove_junk([Volume::sphere_on_ground(center, 2_000.0)])
    .await?;
ctx.report().set("junk_removed", junk.total);
  • ctx.destroy принимает всё, что превращается в Obj: Eid, сущность мира, имя юнита или статика. DCS не шлёт события; мир сразу получает UnitGone с причиной Despawned, а FARP вместе со статиком теряет свой аэродром.
  • Уничтожение FARP не обещано: по сообщениям, DCS не убирает FARP вызовом destroy() (на живом DCS это ещё не измерено). Поэтому после destroy() статика или груза слой Lua на следующем кадре DCS проверяет, исчез ли объект. Если DCS его оставил, ctx.destroy отвечает Error::Lua («DCS did not remove …»): UnitGone не приходит, статик и аэродром FARP в мире остаются живыми. Ответ на уничтожение статика из-за этого приходит на кадр позже; юниты, группы и оружие отвечают как раньше.
  • Объекты карты (здания, мосты) не уничтожаются: Error::Unavailable (в DCS это работает неправильно).
  • Оружие в полёте и катапультировавшиеся пилоты уничтожаются по Eid из события: Obj::weapon(&w) для WeaponSnap из Shot или Hit, Obj::snap(&s) для снимка пилота (оба — None для Eid 0; страница Логика на Rust, «Оружие и катапультировавшиеся пилоты»). Они не сущности мира: UnitGone не приходит, повтор — Error::Gone. Что DCS делает с ракетой и пилотом после destroy, ещё не измерено (живые проверки EVT-L10, EVT-L8).
  • С ревизией 1 group.destroy() тоже не трогает группу с игроком; .allow_player() снимает защиту.
  • ctx.remove_junk берёт от 1 до 16 объёмов: шар, бокс, отрезок, пирамида и круг на карте (или круглая зона сценария). Многоугольник, зона-четырёхугольник и область вокруг объекта DCS точно не выразит — Error::Invalid, движок не расширяет объём молча. Повтор безопасен: второй раз удалять нечего. Что именно DCS считает мусором, не документировано.

Пакет спавнов#

Постоянный сервер начинает с восстановления кампании: сотни групп и статиков. ctx.spawn_batch() собирает их в одну команду с одним ключом: элементы строятся как обычно (ctx.spawn_group(..), ctx.spawn_static(..)), но не ожидаются, а добавляются в пакет.

// Восстановление кампании: одна команда, один ключ; движок проверяет весь пакет сразу.
let mut batch = ctx.spawn_batch();
let cap = batch.add_group(
    ctx.spawn_group(templates::RED_CAP.named("Red CAP 1"))
        .from_airbase(airbases::NALCHIK, StartType::Runway),
);
let farp = batch.add_static(
    ctx.spawn_static("FARP", "USA")
        .named("FARP North")
        .at(zones::TARGET.center(), 0.0)
        .heliport(Heliport::new()),
);
for (name, p) in saved {
    batch = batch.static_object(
        ctx.spawn_static(".Ammunition depot", "USA")
            .named(name.as_str())
            .at(*p, 0.0)
            .on_conflict(OnConflict::Keep),
    );
}
// Ограничитель спавна раздаёт элементы по времени: ответ приходит после последнего.
let out = batch.key("restore-turn-7").await?;
let cap: Group<Air> = out.get(&cap)?; // типизированный результат элемента
let farp: SpawnedStatic = out.get(&farp)?;
for item in out.items.iter().filter(|i| !i.is_ok()) {
    // Ничего не откатывается: у каждого элемента свой результат.
    ctx.report().set(
        item.name.as_str(),
        item.error().map_or("skipped", |e| e.code()),
    );
}
  • Пакет проверяется целиком до отправки: каждый элемент — проверками своей команды (шаблон, имя, таблица типов статиков), имена внутри пакета не повторяются. Один плохой элемент — ошибка всей команды с номером элемента, в DCS не уходит ничего. От 1 до 512 элементов. Имя, которое уже занято в мире (живая группа, статик) или спавном в полёте, — ошибка только этого элемента (NAME_CONFLICT), остальные ставятся; с .stop_on_error() элементы после него пропускаются. Ограничитель спавна пакет делит по очереди с другими спавнами: спавн другой логики не ждёт конца пакета.
  • Ограничитель спавна (по умолчанию 2 группы и 24 юнита в секунду; статик считается одной группой и одним юнитом) раздаёт элементы по кадрам: ответ приходит, когда ответил последний, а уже поставленные элементы тем временем в мире и видны игрокам. Каждый элемент сразу применяется к миру как своя команда: статик получает Birth, задачу новой группе движок придерживает, как после spawn_group. Срок по умолчанию — срок полосы BULK плюс время, которое нужно ограничителю.
  • Ничего не откатывается. Команда успешна, если пакет запустился, что бы ни сделали элементы: SpawnedBatch::items — результат каждого по порядку, out.get(&slot) — типизированный (Group<K> или SpawnedStatic) либо ошибка, которую вернула бы команда элемента.
  • .stop_on_error(): элементы идут по одному, первая ошибка останавливает пакет, остальные помечены skipped (Error::Rejected) и в DCS не уходят. Срок пакета тоже останавливает его (skipped с Error::Timeout).
  • Один ключ на пакет: повтор с тем же ключом и тем же телом — сохранённый результат, ничего не ставится второй раз. Свои .key, .timeout, .after у элементов не действуют. В sortie dev пакет без .key(..) отклоняется.
  • Если связь с миссией оборвалась посреди пакета, команда — Error::Unavailable. Повтор с тем же ключом до полного снимка мира после переподключения отвечает Error::Unavailable и называет элементы, о которых неизвестно, запустились ли они. После снимка повтор продолжает пакет: найденные по имени элементы отмечены settled (их Eid — найденный объект), остальные ставятся, ни один не ставится дважды.
  • Возможность — caps::SPAWN_BATCH (Возможности движка). Если владелец движка выключил spawn_static или spawn_group, пакет с таким элементом отклоняется (Error::Rejected, Error::capability() называет операцию элемента).
  • Живая проверка OBJ-T31 (300 групп и 100 статиков, время кадра сервера, обрыв связи посреди пакета) ещё не проведена; kept у статика из пакета всегда false.
