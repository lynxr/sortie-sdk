Склады: запас аэродромов и грузов#

ctx.warehouse(sel).stock() читает запас одного склада, ctx.warehouses_stock(..) — до 64 складов одним запросом. Это типизированный запрос API ревизии 3, а не вызов DCS: движок проверяет весь список до отправки, у каждого склада свой ответ или своя ошибка, а безлимитный класс так и называется безлимитным, а не нулём и не огромным числом. Запрос ничего не меняет ни в DCS, ни в мире движка, ключ ему не нужен. Склад — аэродрома (в том числе FARP и корабля), груза-статика или по имени склада в DCS; селектор — sortie::sel::WarehouseSel.

Меняет запас команда ctx.warehouse_op() (тоже API ревизии 3, раздел Изменить запас): поставить, добавить, убрать и перевести со склада на склад до 16 замен одной командой, в одном кадре DCS, всё или ничего. Сырые обёртки set_item, add_item, remove_item и жидкостные устарели (#[deprecated]).

Как DCS называет предметы и какой у каждого wsType, говорит запрос ctx.item_names() (раздел Имена предметов): DCS отвечает сама, во время игры, — угадывать строки не нужно.

Весь склад#

#[sortie::mission(api_rev = 3)] // ctx.warehouse(..).stock() — API ревизии 3
pub async fn count_missiles(ctx: Ctx<MyMission>, _start: Start) -> sortie::Result<()> {
    // Весь склад Нальчика: самолёты, оружие и топливо, каждый класс — безлимитный или список.
    let stock = ctx.warehouse(airbases::NALCHIK).stock().await?;
    match &stock.weapons {
        // Пустой класс DCS считается безлимитным: так DCS, по сообщениям, отдаёт безлимитный.
        Some(StockClass::Unlimited) => ctx.report().set("weapons", "без лимита"),
        // Ограниченный: имя предмета, как его называет DCS, и сколько его.
        Some(StockClass::Limited(items)) => {
            let amraam = items
                .get("weapons.missiles.AIM_120C")
                .copied()
                .unwrap_or(0.0);
            ctx.report().set("amraam", amraam);
        }
        _ => {}
    }
    // Топливо — по имени жидкости (килограммы, но единицу DCS не документирует).
    if let Some(Liquids::Amounts(fuel)) = &stock.liquids {
        let jet = fuel.get(&Liquid::JetFuel).and_then(|a| a.count());
        ctx.report().set("jet_fuel", format!("{jet:?}"));
    }
    ctx.end_session(Outcome::Draw).await
}
  • Без .items(..) и .liquids() запрос читает склад целиком (Warehouse.getInventory): WarehouseStock { aircraft, weapons, liquids }. aircraft и weapons — StockClass: StockClass::Unlimited или StockClass::Limited(map) — имя предмета, как его называет DCS ("weapons.missiles.AIM_120C", тип самолёта), и сколько его. class.get(имя) — Some(Amount::Unlimited) в безлимитном классе, Some(Amount::Counted(n)) для предмета из списка, None — ограниченный класс его не перечислил. None у самого класса — DCS его не отдала.
  • Безлимитный класс. DCS, по сообщениям, отдаёт безлимитный класс пустой таблицей; запрос так его и читает: пустой класс — StockClass::Unlimited. Отдаёт ли DCS пустой таблицей и ограниченный класс, в котором ничего нет, не известно (живая проверка AWC-T25). Склад аэродрома без munitions в сценарии (генератор) безлимитный во всех классах.
  • liquids — Liquids::Unlimited или Liquids::Amounts(map) по жидкости: Liquid::JetFuel, AviationGasoline, Mw50 (водо-метаноловая смесь), Diesel (DCS нумерует их 0..3, номер, которого SDK не знает, — Liquid::Unknown("unknown(<n>)")). Единицу количества DCS не документирует; считаем, что это килограммы (в редакторе миссий начальный запас задаётся в тоннах; не измерено).
  • Нагрузка на DCS: getInventory — тяжёлый вызов (класс heavy в каталоге), поэтому слой Lua читает целиком один склад за кадр. Большой склад он копирует по 400 записей за кадр: первые — в кадре вызова, остальные — в следующих, и следующий склад читается после копии; ответ приходит из кадра, в котором прочитан последний. В одном ответе — не больше 20 000 записей всех складов вместе; склад, который не поместился, и каждый склад после него — Error::Rejected (спросите его отдельно). Сколько стоит в кадре сам getInventory большого склада, решает DCS. Это оценки, стоимость в кадре ещё не измерена (AWC-T25).

Нужные предметы и топливо#

// Только нужные предметы — getItemCount каждого, дешевле всего склада. Предмет — имя или
// wsType из четырёх чисел; ответ — в том же порядке.
let s = ctx
    .warehouse(airbases::NALCHIK)
    .stock()
    .items([
        WarehouseItem::from("weapons.missiles.AIM_120C"),
        WarehouseItem::from([4, 4, 7, 22]), // AIM-9M по wsType
    ])
    .liquids() // и четыре жидкости, getLiquidAmount каждой
    .await?;
match s.count("weapons.missiles.AIM_120C") {
    Some(Amount::Counted(n)) => ctx.report().set("amraam", n),
    // Число выше 2^29: DCS, по сообщениям, так отвечает про безлимитный склад.
    Some(Amount::Unlimited) => ctx.report().set("amraam", "без лимита"),
    None => {}
}
  • .items([..]) считает только эти предметы (Warehouse.getItemCount каждого), до 64, каждый не больше одного раза; предмет — имя или wsType из четырёх чисел ([4, 4, 7, 22], WarehouseItem — тот же тип, что у сырых обёрток item_count(..)). .liquids() читает четыре жидкости (Warehouse.getLiquidAmount каждой). С любым из них склад целиком не читается: это дешевле — 64 вызова DCS за кадр, около 4 на поиск склада и по одному на чтение (склады по одному предмету — 13 за кадр; оценка, AWC-T25).
  • stock.items — Vec<ItemCount { item, amount }> в порядке списка, stock.count(предмет) — amount этого предмета. Amount::Counted(n) — как ответила DCS; Amount::Unlimited — DCS ответила числом больше 2^29: так она, по сообщениям, отвечает про безлимитный склад (2^29 — порог, которым пользуется MOOSE; не измерено). Если же DCS отвечает про безлимитный класс маленьким числом, одно это чтение его не отличит: тип класса показывает только склад целиком. То же для жидкостей из .liquids(): безлимитными они бывают только по этому порогу.
  • Имя предмета и его wsType, по сообщениям, — один и тот же запас; это не измерено (AWC-T6). Какой wsType у имени, говорит ctx.item_names().

Много складов#

// До 64 складов одним запросом: аэродрома, груза (статика) или по имени склада в DCS.
let read = ctx
    .warehouses_stock([
        WarehouseSel::airbase(airbases::NALCHIK),
        WarehouseSel::airbase(AirbaseSel::name("FARP North")),
        WarehouseSel::named("Kutaisi"),
    ])
    .items(["weapons.missiles.AIM_120C"])
    .await?;
for w in &read.warehouses {
    match (&w.value, w.error()) {
        (Some(s), _) => {
            let n = s.count("weapons.missiles.AIM_120C");
            ctx.report().set(&w.name, format!("{n:?}"));
        }
        // Своя ошибка склада: Error::Gone — его нет в DCS или мир держит базу мёртвой.
        (None, Some(e)) => ctx.report().set(&w.name, e.code()),
        (None, None) => {}
    }
}
ctx.report().set("answered", read.ok_count());
  • До 64 складов (sortie::cmd::MAX_STOCK_WAREHOUSES), каждый не больше одного раза — по имени в DCS, каким бы селектором он ни был назван (склад аэродрома по имени и он же через WarehouseSel::named — дважды). Результат — WarehousesRead { warehouses }, по одному WarehouseRead { warehouse, name, eid, value } на склад в порядке списка: warehouse — склад, как его понял движок (аэродром или статик по Eid мира, если мир его держит живым), name — имя в DCS, eid — Eid аэродрома или статика в мире, value — запас, None при ошибке этого склада; w.error() — его ошибка: Error::Gone (склада нет в DCS, мир держит базу или статик мёртвыми, устаревший Eid), Error::Lua (чтение DCS упало), Error::Rejected (не поместился в ответ). read.ok_count() — сколько складов ответили. Сам запрос при этом успешен.
  • Имя, которого мир не знает, запрос всё равно отправляет (склад мог добавить другой скрипт; DCS ответит или скажет Error::Gone); мёртвую базу и устаревший Eid движок отвечает сам, до DCS они не доходят. Целиком запрос отвергается (Error::Invalid) только когда список пуст или длиннее 64, склад или предмет в нём дважды, предметов больше 64, у предмета пустое имя или число wsType больше 2^31 − 1, символа нет в сценарии или Eid груза — не статика.
  • Полоса QUERY, по умолчанию 10 с на ответ.

Изменить запас#

// Колонна дошла: ракеты из Кутаиси в Нальчик, топливо Нальчику, две AIM-9M списаны —
// одной командой, в одном кадре DCS, всё или ничего.
let out = ctx
    .warehouse_op()
    .transfer(
        airbases::KUTAISI,
        airbases::NALCHIK,
        "weapons.missiles.AIM_120C",
        6.0,
    )
    .add(airbases::NALCHIK, Liquid::JetFuel, 5_000.0)
    .remove(airbases::KUTAISI, [4, 4, 7, 22], 2.0) // AIM-9M по wsType
    .key("convoy-3-arrived") // каждая команда склада — с ключом
    .await?;
if out.applied {
    // У каждой замены — счёт до неё и что DCS прочла после; у перевода — и у склада `to`.
    let nalchik = out.changes[0].to.as_ref().and_then(|t| t.after);
    ctx.report().set("nalchik_amraam", format!("{nalchik:?}"));
} else {
    // Ничего не изменилось. Почему — у замен, что не прошли проверку.
    for c in out.failed() {
        let why = match c.outcome {
            StockOutcome::NotEnough => "мало на складе",
            StockOutcome::Unlimited => "склад без лимита",
            StockOutcome::Gone => "склада нет в DCS",
            StockOutcome::Aliased => "один предмет назван именем и wsType",
            _ => "DCS не приняла замену",
        };
        ctx.report()
            .set(&c.warehouse.name, format!("{why}: {}", c.message));
    }
}
  • Замены: .set(склад, что, n) — поставить счёт (количество жидкости) на n, .add(..) — добавить, .remove(..) — убрать, .transfer(откуда, куда, что, n) — перевести с одного склада на другой. что — StockItem: предмет (имя "weapons.missiles.AIM_120C", wsType [4, 4, 7, 22], WarehouseItem) или жидкость (Liquid::JetFuel, AviationGasoline, Mw50, Diesel). Предмет считается целыми числами до 1 000 000, жидкость — до 100 000 000 (килограммы, единицу DCS не документирует); set принимает и 0, остальные — больше 0. До 16 замен одной командой (sortie::cmd::MAX_STOCK_CHANGES), по порядку; один склад может стоять во многих заменах.
  • Всё или ничего. В том кадре, в котором команда выполняется, слой Lua сначала находит каждый склад и читает каждый счёт, который трогают замены, и проверяет замены по порядку — с учётом того, что сделают замены перед ней: склад есть в DCS, запас не безлимитный, для remove и transfer его хватает. Если не прошла хоть одна, ничего не меняется: out.applied == false, у не прошедших — своя причина, у остальных NotApplied. Иначе замены применяются по порядку; перед каждым шагом счёт читается снова и должен быть тем, что оставила ему проверка, а после шага — тем, что даёт замена. Если DCS при этом падает или счёт не тот, всё, что уже сделано, откатывается (каждый счёт ставится обратно, set*), у сделанных замен — Undone. Всё это — в одном кадре: другой скрипт между проверкой и заменой ничего не изменит.
  • Перевод — один шаг: со склада откуда убирается, на склад куда добавляется в том же кадре; если добавить не вышло, убранное возвращается. Запас никогда не уходит, не придя.
  • Убрать больше, чем есть, нельзя: это NotEnough, команда ничего не меняет. До нуля замена не обрезается (что делает с нехваткой сам removeItem DCS, не измерено); формы «сколько есть» в этой версии нет — прочитайте запас сначала.
  • Ответ — StockChanges { applied, undo_failed, changes }, по одному StockChanged на замену в порядке списка: what — что меняли, outcome — исход, message — почему (у всех, кроме Done), warehouse — склад замены (у перевода — тот, откуда), to — у перевода склад, куда. У стороны (StockSide) — name и eid склада, before — счёт, с которого замена начинает (что прочла DCS, плюс замены перед ней), after — что DCS прочла после неё (после отката, если он был), unlimited — DCS ответила числом больше 2^29. out.failed() — замены, из-за которых команда не применилась.
StockOutcomeЧто случилось
Doneприменена, after — что прочла DCS
NotAppliedзамена прошла бы, но не прошла другая: ничего не изменилось
Undoneприменена и откачена: позже упала другая замена
UndoFailedприменена, а откат не вернул счёт; запас — как говорит after, undo_failed == true
Unlimitedзапас безлимитный (счёт больше 2^29, у перевода — с любой стороны): DCS, по сообщениям, на нём ничего не меняет, поэтому замена отвергнута до изменений
NotEnoughremove или transfer больше, чем на складе
Goneсклада нет в DCS
DcsErrorчтение или замена DCS упала (message называет функцию)
UnchangedDCS приняла замену, но счёт не стал таким, как надо (так повёл бы себя безлимитный склад, про который DCS отвечает маленьким числом; не измерено); сделанное до неё откачено
Aliasedк её очереди счёт уже не тот, что оставила проверка: его сдвинула более ранняя замена той же команды под другой формой предмета (имя и его wsType или два имени одного wsType — для DCS это один запас); замена не выполнялась, сделанное до неё откачено
  • Безлимитный запас никогда не считается нулём и замена на нём — сделанной: счёт больше 2^29 — Unlimited, а если DCS ответит маленьким числом и ничего не изменит, — Unchanged. Не отличить только set на счёт, который DCS уже показывает (он Done). На что это опирается, не измерено (живая проверка AWC-T26).
  • Ключ. В режиме dev (и на движке с --require-keys) каждой команде склада нужен .key(..), иначе Error::Invalid и ничего не отправляется: перезагрузка логики выполняет её снова, и без ключа add, remove и transfer сдвинули бы запас ещё раз, а set поставил бы счёт обратно поверх того, что успели израсходовать. Повтор с тем же ключом возвращает сохранённый ответ и запас не трогает — и отказ тоже: чтобы попробовать снова, дайте новый ключ.
  • Целиком команда отвергается (Error::Invalid, в DCS ничего не уходит), если в ней нет замен или их больше 16, склада нет в мире движка (имя, которого мир не держит живым; символ, которого нет в сценарии), перевод — на тот же склад, число вне пределов или у предмета дробный счёт, жидкость — Liquid::Unknown; мёртвая база или устаревший Eid — Error::Gone. Сама команда успешна, даже когда замены не применились: смотрите out.applied.
  • Один предмет по имени и по wsType в одной команде не называйте: слой Lua не знает, что это один запас, и проверяет их как два счёта. Чтение перед шагом это находит: замена — Aliased, команда откатывается, и что бы DCS ни делала с нехваткой, лишнее не убирается и запас из ничего не появляется. Чтобы называть одной формой, переведите wsType в имя через ctx.item_names(): движок сам предметы команды не переписывает.
  • Нагрузка на DCS: все замены — в одном кадре (без этого нет «всё или ничего»), примерно 4 вызова DCS на set, add или remove, 8 на перевод, около 4 на каждый склад и до 3 на шаг отката. 16 замен — граница списка, а не то, что укладывается в долю кадра: 16 замен одного предмета на одном складе — около 50 вызовов (примерно 0,5 мс), 16 переводов между 32 складами — около 260 (примерно 2,6 мс), с откатом больше. Переводы между многими складами делите на несколько команд — у каждой свой кадр и своё «всё или ничего». Это оценки (AWC-T26). Полоса REALTIME, по умолчанию 10 с на ответ.

Только set — тоже с ключом:

// Пополнение в начале миссии — тоже с ключом: без него перезагрузка логики поставила бы
// эти числа снова, поверх того, что успели израсходовать.
let out = ctx
    .warehouse_op()
    .set(airbases::NALCHIK, "weapons.missiles.AIM_120C", 20.0)
    .set(airbases::NALCHIK, Liquid::Diesel, 0.0)
    .key("restock-nalchik")
    .await?;
ctx.report().set("restocked", out.applied);

Имена предметов#

// Как эта DCS называет то, что знает, и wsType каждого — один раз за процесс DCS,
// дальше движок отвечает из памяти.
let names = ctx.item_names().await?;
// Имя -> wsType и обратно.
if let Some(ws) = names.ws_type_of("weapons.missiles.AIM_120C") {
    let same: Vec<&str> = names.names_of(ws).collect();
    ctx.report().set("amraam_ws", format!("{ws:?} {same:?}"));
}
// Свой список предметов кампании проверить до первого запроса склада.
let mine = ["weapons.missiles.AIM_120C", "weapons.bombs.Mk_82"];
let unknown: Vec<&str> = mine.into_iter().filter(|n| !names.knows(*n)).collect();
ctx.report().set("unknown_items", format!("{unknown:?}"));
// Только нужные: имя или wsType; чего DCS не знает — в `unknown`.
let some = ctx
    .item_names()
    .items([WarehouseItem::from([4, 4, 7, 22])])
    .await?;
for n in &some.names {
    ctx.report().set(&n.name, format!("{:?}", n.ws_type));
}
  • ctx.item_names() спрашивает у DCS, к которой подключён движок, всё, что она знает: Warehouse.getResourceMap() (есть с DCS 2.8.8) отдаёт каждый объект по имени с его wsType. Оружие там названо так, как его называют склады: "weapons.missiles.AIM_120C", "weapons.bombs.Mk_82"; самолёты и другая техника — по типу ("F-16C_50"). В SDK и в репозитории никакой таблицы DCS нет: последнее число wsType у многих предметов DCS назначает сама, когда грузит свою базу, поэтому оно может отличаться от сборки к сборке и от набора модулей; верный ответ знает только запущенная DCS.
  • Ответ — ItemNames { names, unknown, total, skipped, dcs_version, cached, source }: names — ItemName { name, ws_type } по алфавиту, каждое имя один раз; ws_type — None, где DCS даёт {0, 0, 0, 0} (так у снарядов, статиков и башен: это не тип предмета, склад о нём не спросить). names.get(имя), names.ws_type_of(имя) — wsType имени, names.names_of(ws) — все имена с этим wsType (обычно одно), names.knows(предмет) — знает ли DCS имя или wsType; n.item() — предмет для запросов склада и ctx.warehouse_op(). total — сколько имён в карте DCS, skipped — сколько записей слой Lua пропустил (не имя или не четыре целых числа), source — как слой позвал DCS.
  • .items([..]) — только эти (до 64, каждый не больше одного раза): имя даёт свою запись, wsType — все записи с ним; чего DCS не знает — в unknown, в порядке списка. Так проверяют предметы кампании (оружие по имени, вертолёты и самолёты по типу) до наполнения склада: в ctx.warehouse_op() идут только names, опечатка остаётся в unknown. Записи Warehouse.getResourceMap в каталоге вызовов DCS нет — его карту читает этот запрос.
  • Один раз за процесс DCS. Движок читает карту DCS при первом запросе и держит её в памяти для этого процесса DCS и её версии; следующие запросы он отвечает сам, ничего не отправляя (cached == true), — и после перезапуска миссии в той же DCS. Другой процесс DCS (перезапуск DCS, обновление) — карта читается снова. На диск движок её не пишет. Читайте имена один раз в начале миссии и держите ItemNames у себя: ответ без .items(..) — вся карта, тысячи имён.
  • Нагрузка на DCS: карту DCS строит одним вызовом (сколько это стоит в кадре, не измерено), слой Lua копирует её в следующих кадрах, по 400 записей за кадр, — карта в 10 000 записей занимает около 25 кадров. Пока она читается, другие тяжёлые вызовы ждут. Больше 30 000 записей — Error::Rejected. Это оценки (AWC-T27). Полоса QUERY, по умолчанию 10 с на ответ.
  • Ключа запрос не принимает: с .key(..) он — Error::Invalid, и ничего не отправляется. Ответ — вся карта DCS, движок держит её только в памяти и в своё хранилище не пишет, а повтор и так отвечается из памяти.
  • Генератор по-прежнему берёт munitions аэродрома по wsType: имена знает только запущенная DCS, а сценарий собирается без неё. Если хочется писать сценарий именами, держите свою таблицу имя → wsType, прочитанную ctx.item_names() на своей DCS.

Ревизия и возможности#

  • Логика объявляет #[sortie::mission(api_rev = 3)]; с меньшей ревизией запрос — Error::Revision, против движка с ревизией API ниже 3 — Error::EngineTooOld, и ничего не отправляется.
  • Возможность caps::WAREHOUSE_STOCK ("warehouse_stock"): включена по умолчанию; владелец движка выключает её в engine.toml ([operations] disable = ["warehouse_stock"]), тогда запрос — Error::Rejected. Если в сборке DCS нет Airbase.getWarehouse, Warehouse.getInventory, Warehouse.getItemCount или Warehouse.getLiquidAmount, её состояние — MISSING_IN_DCS. Слою Lua 0.3.x нужен sortie install, иначе она NOT_IMPLEMENTED.
  • Сырые чтения каталога ctx.dcs().warehouse(..).inventory(..), .item_count(..) и .liquid_amount(..) остаются и не устарели: они отдают ответ DCS как есть.
  • ctx.warehouse_op() — тоже API ревизии 3 (Error::Revision, Error::EngineTooOld так же). Возможность caps::WAREHOUSE_OP ("warehouse_op"): включена по умолчанию, выключается так же ([operations] disable = ["warehouse_op"], тогда команда — Error::Rejected); если в сборке DCS нет Airbase.getWarehouse, Warehouse.getItemCount, setItem, addItem или removeItem — MISSING_IN_DCS. Жидкостных функций она не проверяет: если в DCS нет нужной замене, команда — Error::Unavailable (MISSING), а замены предметов работают.
  • Сырые изменения каталога set_item, add_item, remove_item, set_liquid_amount, add_liquid, remove_liquid устарели (superseded_by = "warehouse_op"): они остаются, но выключены по умолчанию и ничего не проверяют.
  • ctx.item_names() — тоже API ревизии 3 (Error::Revision, Error::EngineTooOld так же). Возможность caps::ITEM_NAMES ("item_names"): включена по умолчанию, выключается так же ([operations] disable = ["item_names"], тогда запрос — Error::Rejected); если в сборке DCS нет Warehouse.getResourceMap (DCS до 2.8.8), её состояние — MISSING_IN_DCS, а запрос — Error::Unavailable.

Что не измерено#

Что DCS отдаёт безлимитный класс пустой таблицей, а ограниченный, в котором ничего нет, — иначе; чем DCS отвечает getItemCount и getLiquidAmount на безлимитном складе; в каких единицах жидкости; сколько записей у ограниченного склада настоящей миссии и сколько стоит в кадре один склад — на реальной DCS ещё не измерено (живая проверка AWC-T25; проба wide_probe, шаг Foothold, читает склад Сенаки-Колхи с ограниченными ракетами и безлимитный склад Кутаиси рядом с сырыми вызовами). Что имя и wsType предмета — один запас и что Airbase.getWarehouse работает у аэродрома, FARP и корабля — тоже (AWC-T6, CAT-L3).

Для ctx.warehouse_op() не измерено (живая проверка AWC-T26): что setItem, addItem и removeItem ограниченного склада DCS читает обратно в том же кадре; что безлимитный склад отвечает числом больше 2^29 и замена на нём ничего не делает; с какой точностью DCS хранит жидкости (замена жидкости считается сделанной, если прочитанное отличается не больше чем на миллионную долю и не больше чем на 1 кг); сколько стоит в кадре одна замена. Проба wide_probe (шаг Foothold) переводит AIM-120C с Сенаки-Колхи на ограниченный склад Кобулети и обратно, пробует убрать больше, чем есть, и одну замену на безлимитном Кутаиси, а потом возвращает запас.

Для ctx.item_names() не измерено (живая проверка AWC-T27): что Warehouse.getResourceMap есть и в какой форме его звать (без аргументов или со складом); что его имена — те, которыми пользуются склады, а wsType — четыре целых числа; что имя и wsType из карты — один запас; сколько записей в карте и сколько стоит её чтение. Проба wide_probe (шаг Foothold) читает карту, сверяет AIM-120C с wsType, который кладёт на склад сценарий, проверяет, что каждое оружие ограниченного склада Сенаки-Колхи есть в карте и что ракеты по имени и по wsType из карты дают один счёт; безлимитный Кутаиси — для записи.

Тестирование#

FakeDcs хранит запас каждого склада: dcs.set_warehouse_stock(имя, FakeStock::..) задаёт его по классам — так, как его записали бы в .miz munitions сценария (манифест их не несёт), и перезагрузка миссии начинает склад с него же. Склад, которого тест не задал, безлимитный во всех классах, как аэродром без munitions. Например, FakeStock::unlimited().weapons([("weapons.missiles.AIM_120C", 20.0)]) — 20 AIM-120C и больше никакого оружия, самолёты и топливо без лимита; FakeStock::limited() — все классы ограничены и пусты; .aircraft([..]) и .liquids([(0, 1500.0)]) (номер жидкости DCS: 0 — авиатопливо) задают остальные классы.

В безлимитном классе FakeDcs, как DCS по сообщениям, отдаёт пустую таблицу в getInventory, число FAKE_UNLIMITED_COUNT (2^30) в getItemCount и getLiquidAmount и ничего не меняет сырыми set_item, add_item, remove_item. Предмет — в классе самолётов, если тот его перечисляет или FakeDcs знает такой тип самолёта или вертолёта, иначе в оружии; wsType — свой запас, отдельно от имени, если тест не дал карту имён (ниже). dcs.warehouse_stock(имя) и dcs.warehouse_count(имя, предмет) — что на складе сейчас; сырые вызовы Warehouse.*, запрос и ctx.warehouse_op() работают с одним запасом.

dcs.set_item_names([(имя, [a, b, c, d]), ..]) — что FakeDcs отвечает на ctx.item_names() (карта Warehouse.getResourceMap). Пока тест её не задал, карта пуста: FakeDcs данных DCS не держит, имена своей миссии тест даёт сам. Карта — процесса DCS, перезагрузка миссии её не сбрасывает. wsType, которому карта даёт ровно одно имя, в складах FakeDcs — запас этого имени (как в DCS, по сообщениям); без карты wsType — свой запас.

ctx.warehouse_op() в FakeDcs проверяет и применяет замены, как слой Lua: безлимитный класс отвечает FAKE_UNLIMITED_COUNT и даёт Unlimited, нехватка — NotEnough, склад, которого нет, — Gone. Имя и wsType одного предмета проверка считает двумя счетами, как слой Lua, а перед шагом замена находит общий запас: Aliased и откат. Замены FakeDcs не падают, поэтому DcsError и Unchanged в нём не встречаются (их проверяют тесты слоя Lua). Команда — изменение: она есть в dcs.command_log().
