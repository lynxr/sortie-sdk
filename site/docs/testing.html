Тестирование#

Что есть в 0.1.0#

В этой версии SDK нет тестов без DCS: фальшивая DCS (FakeDcs) содержит движок, а движок в SDK не входит. Атрибут #[sortie::test] в SDK 0.1.0 не компилируется и говорит об этом прямо:

error: #[sortie::test] runs the logic against FakeDcs, which is not part of Sortie SDK 0.1; tests without DCS arrive in SDK 0.2. Test against a live DCS with `sortied --dev` for now.

Что можно проверить уже сейчас:

  • Компиляция. Символы сценария типизированы: опечатка в имени группы, приказ авиации наземной группе, символ другого сценария — это ошибки cargo build, а не сюрпризы в игре. #[sortie::mission] проверяет сигнатуру функции миссии.
  • Обычные тесты Rust. Свои функции и геометрию зон можно проверять cargo test: константы зон несут координаты из scenario.lock.json.
#[test]
fn the_target_lies_on_the_front_line() {
    assert!(zones::FRONT.contains(zones::TARGET.center()));
    let gap = zones::TARGET.center().distance(zones::PATROL.center());
    assert!(gap < km(1).meters(), "the patrol is centred on the target");
}
  • Сценарий. python scenario.py build собирает миссию без движка и ловит ошибки имён, стран, аэродромов, типов pydcs и правило аэродрома игроков. В CI добавьте python scenario.py lock --check и build --locked: они падают, если scenario.lock.json устарел.
  • Типы юнитов. python scenario.py validate спрашивает запущенную DCS, знает ли она каждый тип сценария.

Проверка в живой DCS#

Удобный цикл на одной машине:

  1. Запустите sortied --dev и логику (cargo run).
  2. Зарегистрируйте сборку (python scenario.py register) и откройте миссию в одиночной игре.
  3. Меняйте логику и перезапускайте только её процесс. DCS и миссию перезапускать не нужно: новый процесс подключится к той же сессии и получит Start::AfterCrash. Команды с ключами, которые уже выполнились, второй раз в DCS не уйдут, а ctx.timer продолжит ждать тот же дедлайн.
  4. Смотрите события в python scenario.py watch или sortie events, итоги — в python scenario.py results, состояние движка — в sortie status и sortie top.
  5. Ускорение времени в DCS ускоряет и логику: ctx.sleep и ctx.timer считают модельное время.

Чтобы проверить сценарий целиком с начала, перезапустите миссию: в одиночной игре из меню DCS, у хоста сетевой игры — python scenario.py restart. Логика получит новую сессию.

Что проверять вручную перед выпуском миссии:

  • миссия стартует, логика получает сессию (sortie status показывает её);
  • условия срабатывают, когда должны: войдите в зону, уничтожьте цель;
  • перезапуск процесса логики в середине миссии ничего не повторяет;
  • в сетевой игре игроки занимают все слоты.

Что будет в 0.2#

В SDK 0.2 появятся тесты без DCS:

  • #[sortie::test(manifest = "...")] запускает настоящий движок в процессе теста и фальшивую DCS, которая говорит с ним по настоящему протоколу;
  • мир строится из того же manifest, что и миссия; время виртуальное, поэтому десять минут миссии проходят за миллисекунды и прогоны воспроизводимы;
  • тест управляет фальшивой DCS: ставит юниты, убивает группы, двигает время и проверяет флаги, опции ИИ и точный поток команд в DCS;
  • известные странности DCS (потерянные события гибели, двойное рождение, пустой инициатор попадания) включаются в тесте одной строкой.
