# Объекты: статики, уничтожение, мусор

Операции ревизии API 1 работают с объектами мира, у которых нет шаблона в сценарии:
`ctx.spawn_static` ставит статический объект, груз или FARP, `ctx.destroy` убирает любой юнит,
статик, груз, оружие в полёте или катапультировавшегося пилота, `ctx.remove_junk` чистит обломки
и воронки, `ctx.spawn_batch` ставит много групп и статиков одной командой. Как группа из шаблона
встаёт в точку (`.at` и `.at_formation`), описано [ниже](#группа-из-шаблона-в-точке). Это
типизированные операции, а не
[вызовы DCS](dcs.md): движок сам следит за именем, скоростью спавна и сразу сообщает миру, что
изменилось.

## Статики

<!-- snippet: sdk-objects-statics -->
```rust
#[sortie::mission(api_rev = 1)] // статики, destroy и remove_junk — API ревизии 1
pub async fn statics(ctx: Ctx<MyMission>, _start: Start) -> sortie::Result<()> {
    let p = zones::TARGET.center(); // MapPoint
    // Категорию и модель DCS движок берёт из своей таблицы типов.
    let depot = ctx
        .spawn_static(".Ammunition depot", "USA")
        .named("Depot North")
        .at(p, 0.0)
        .key("depot-north")
        .await?;
    // Статик уже в реплике мира; DCS не шлёт BIRTH для статиков, событие Birth делает движок.
    let alive = ctx.world().entity(depot.eid).is_some_and(|e| e.is_alive());
    // Рабочий FARP — аэродром с позывным и частотой.
    let farp = ctx
        .spawn_static("FARP", "USA")
        .named("FARP North")
        .at(p.toward(90.0_f64.to_radians(), m(500)), 0.0)
        .heliport(
            Heliport::new()
                .callsign("London")
                .frequency_hz(127_500_000.0),
        )
        .key("farp-north")
        .await?;
    // Груз, который может поднять вертолёт; имя по умолчанию — `ammo_cargo#<сессия>-<n>`.
    let crate_ = ctx
        .spawn_static("ammo_cargo", "USA")
        .cargo(800.0, true)
        .at(p.toward(0.0, m(50)), 0.0)
        .key("crate-1")
        .await?;
    ctx.report().set("farp_airbase", farp.airbase.is_some());
    ctx.report().set("crate", crate_.name);
    let _ = alive;
    ctx.end_session(Outcome::Draw).await
}
```

* Тип — имя типа DCS (`"Cafe"`, `".Command Center"`, `"ammo_cargo"`, `"FARP"`, `"Mi-8MT"`),
  страна — ключ DCS (`"USA"`, `"RUSSIA"`); коалиция следует за страной.
* У статика DCS должна быть верная пара «категория — модель», иначе его не видно. Движок берёт
  её по умолчанию из своей таблицы (типы pydcs 1.0.0: укрепления, грузы, склады, FARP,
  самолёты, вертолёты, корабли и техника как статики); заданные `.category(..)` и `.shape(..)`
  важнее таблицы. Знает ли DCS тип, решает сам DCS (`getDescByName` на запущенной сборке):
  неизвестный тип — `Error::Invalid`. Для типа, которого в таблице нет (мод, новая сборка
  DCS), задайте и `.category(..)`, и `.shape(..)`; без одного из них — `Error::Invalid` с
  именем недостающего поля (для самолётов, вертолётов, кораблей и техники модель не нужна).
* `.on_unit(корабль, вперёд_м, вправо_м, угол)` ставит статик на палубу корабля, он движется вместе
  с ним. `.dead()` — обломки, `.hidden()` — не виден на карте F10, `.score(n)` — очки за
  уничтожение, `.livery(..)`, `.raw(таблица)` — дополнительные ключи таблицы DCS (ключ, который
  задаёт метод билдера, отклоняется; код Lua, имена файлов и NaN тоже —
  [проверка сырых таблиц](operations.md#проверка-сырых-таблиц)).
* FARP, площадка и невидимый FARP (`"FARP"`, `"SINGLE_HELIPAD"`, `"Invisible FARP"`) ставятся
  только с `.heliport(..)`: так DCS делает из них аэродром. `SpawnedStatic::airbase` — его Eid,
  в мире у него `host` — статик. Позывной по умолчанию — первый ещё не выданный в этой сессии,
  частота по умолчанию 127,5 МГц AM.
* Статики идут через тот же ограничитель скорости спавна, что и группы (по умолчанию 2 в
  секунду), полосой BULK. В `sortie dev` спавн без `.key(..)` отклоняется.

## Имя — личность

Имя статика уникально среди юнитов и статиков: DCS молча уничтожает живой объект с тем же именем.
Поэтому движок по умолчанию отвечает `Error::NameConflict`, а `.on_conflict(..)` выбирает другое:

<!-- snippet: sdk-objects-conflicts -->
```rust
// Имя — личность статика. Повтор после перезапуска логики:
let depot = ctx
    .spawn_static(".Ammunition depot", "USA")
    .named("Depot North")
    .at(p, 0.0)
    .on_conflict(OnConflict::Keep) // живой статик того же типа — он и есть результат
    .key("depot-north-again")
    .await?;
if depot.kept {
    // ничего не создано
}
// Заменить живой статик новым (игрок в статике не сидит):
ctx.spawn_static(".Command Center", "USA")
    .named("Depot North")
    .at(p, 0.0)
    .on_conflict(OnConflict::Replace) // старый получает UnitGone с причиной Replaced
    .key("depot-north-hq")
    .await?;
```

`Replace` сначала проверяет всё, потом уничтожает старый статик и ставит новый на следующем кадре
DCS. Юнит с этим именем не заменяется: `Error::NameConflict`. Перед постановкой слой Lua ещё
раз смотрит на имя: если DCS не убрал старый статик (так, по сообщениям, бывает с FARP; не
измерено), команда отвечает `Error::Lua` («DCS did not remove …»), новый статик не ставится, а
старый остаётся в мире живым.

`Keep` для живого FARP возвращает и его аэродром в `SpawnedStatic::airbase`, как при первой
постановке: после перезапуска логики повтор спавна снова даёт Eid аэродрома.

## Уничтожение и мусор

<!-- snippet: sdk-objects-destroy -->
```rust
ctx.destroy(Obj::static_object("Depot North"))
    .key("depot-north-gone")
    .await?;
// Юнит с игроком не уничтожается без .allow_player(): у клиентов остаются «призраки».
match ctx.destroy(Obj::unit("Viper 1-1")).key("viper-gone").await {
    Ok(()) | Err(Error::Gone(_)) => {}
    Err(Error::Rejected(_)) => ctx.report().set("viper", "occupied by a player"),
    Err(e) => return Err(e),
}
// Обломки, воронки и мусор в объёмах DCS; результат — что насчитала DCS.
let center = zones::TARGET.center();
let junk = ctx
    .remove_junk([Volume::sphere_on_ground(center, 2_000.0)])
    .await?;
ctx.report().set("junk_removed", junk.total);
```

* `ctx.destroy` принимает всё, что превращается в `Obj`: Eid, сущность мира, имя юнита или
  статика. DCS не шлёт события; мир сразу получает `UnitGone` с причиной `Despawned`, а FARP
  вместе со статиком теряет свой аэродром.
* Уничтожение FARP не обещано: по сообщениям, DCS не убирает FARP вызовом `destroy()` (на
  живом DCS это ещё не измерено). Поэтому после `destroy()` статика или груза слой Lua на
  следующем кадре DCS проверяет, исчез ли объект. Если DCS его оставил, `ctx.destroy` отвечает
  `Error::Lua` («DCS did not remove …»): `UnitGone` не приходит, статик и аэродром FARP в мире
  остаются живыми. Ответ на уничтожение статика из-за этого приходит на кадр позже; юниты,
  группы и оружие отвечают как раньше.
* Объекты карты (здания, мосты) не уничтожаются: `Error::Unavailable` (в DCS это работает
  неправильно).
* Оружие в полёте и катапультировавшиеся пилоты уничтожаются по Eid из события:
  `Obj::weapon(&w)` для `WeaponSnap` из `Shot` или `Hit`, `Obj::snap(&s)` для снимка пилота
  (оба — `None` для Eid 0; страница [Логика на Rust](sdk.md), «Оружие и катапультировавшиеся
  пилоты»). Они не сущности мира: `UnitGone` не приходит, повтор — `Error::Gone`. Что DCS
  делает с ракетой и пилотом после `destroy`, ещё не измерено (живые проверки EVT-L10, EVT-L8).
* С ревизией 1 `group.destroy()` тоже не трогает группу с игроком; `.allow_player()` снимает
  защиту.
* `ctx.remove_junk` берёт от 1 до 16 объёмов: шар, бокс, отрезок, пирамида и круг на карте (или
  круглая зона сценария). Многоугольник, зона-четырёхугольник и область вокруг объекта DCS
  точно не выразит — `Error::Invalid`, движок не расширяет объём молча. Повтор безопасен: второй
  раз удалять нечего. Что именно DCS считает мусором, не документировано.

## Поиск объектов

`ctx.search_objects(объём)` (ревизия API 2: `#[sortie::mission(api_rev = 2)]`) — что DCS находит
внутри объёма функцией `world.searchObjects`: юниты, статики, объекты карты (здания, мосты),
по желанию оружие, грузы и аэродромы. Это чтение: ни в DCS, ни в мире ничего не меняется.
Деревья и лес поиск не находит ([что DCS знает о местности](#что-dcs-знает-о-местности)).

<!-- snippet: sdk-objects-search -->
```rust
#[sortie::mission(api_rev = 2)] // ctx.search_objects — API ревизии 2
pub async fn search(ctx: Ctx<MyMission>, _start: Start) -> sortie::Result<()> {
    use sortie::cmd::ObjectCategory as C;
    let p = zones::TARGET.center();
    // Шар радиусом 300 м на земле: юниты, статики и объекты карты (по умолчанию).
    let found = ctx
        .search_objects(Volume::sphere_on_ground(p, 300.0))
        .categories([C::Unit, C::Static, C::Scenery])
        .await?;
    for o in &found.objects {
        // Юнит или статик из мира — с его Eid; у объекта карты Eid нет, есть его id в DCS.
        let intact = match (o.life, o.life_max) {
            (Some(life), Some(max)) if max > 0.0 => life / max,
            _ => 1.0,
        };
        let in_world = o
            .eid
            .and_then(|eid| ctx.world().entity(eid).map(|e| e.is_alive()));
        let _ = (intact, in_world, o.dcs_id, &o.type_name);
    }
    // Больше лимита (по умолчанию 500, не больше 2000) — `truncated`, остальное не прочитано.
    let busy = found.truncated || !found.objects.is_empty();
```

* У каждого объекта — то, что DCS ответил в момент поиска: категория, имя, тип, точка, `life`
  и `life_max` (жизнь целого объекта, `getDesc().life`), коалиция и id в DCS. Юнит, статик или
  груз, который знает мир, назван своим `eid`: остальное о нём — в `ctx.world()`.
* Объект карты не сущность мира: `eid` нет, есть `dcs_id` — его id на карте. Имя объекта карты —
  тоже этот id текстом (по сообщениям; не измерено).
* Объём — шар, бокс, отрезок, пирамида или круг на карте (круглая зона сценария), как у
  `ctx.remove_junk`; многоугольник и область вокруг объекта — `Error::Invalid`.
* Читается не больше `.limit(n)` объектов (по умолчанию 500, не больше 2000); если в объёме
  больше, `truncated = true`, а остальные не перечислены. Каждый объект — около десятка вызовов
  DCS, так что большой поиск стоит кадра.
* Логика ревизии ниже 2 получает `Error::Revision`, движок ревизии 1 (0.2.x) —
  `Error::EngineTooOld`. Нужен новый слой Lua: `sortie install` и перезапуск DCS.

### Что DCS знает о местности

Скрипт в DCS не видит леса и отдельных деревьев и не знает, какой объём занимают скалы и
модели объектов карты. Ни одна документированная функция DCS этого не даёт, в том числе на
выделенном сервере, поэтому у Sortie нет запроса «свободна ли площадка» и проверки на лес.
Что DCS даёт:

* `land.getSurfaceType` (`ctx.dcs().land().surface_type(..)`) знает пять видов поверхности:
  `LAND`, `SHALLOW_WATER`, `WATER`, `ROAD`, `RUNWAY`. Лес и город — это `LAND`.
* `land.isVisible` и `land.getIP` учитывают только рельеф: деревья и здания линию видимости
  в них не перекрывают. В самой симуляции деревья есть: по журналу изменений DCS техника
  сталкивается с ними (2.9.1) и они закрывают обзор наземному ИИ (2.9.10), но скрипту это не
  видно.
* `ctx.search_objects` находит юниты, статики и объекты карты (здания, мосты), а деревья — нет.
  Это известно из сообщений на форуме ED (бета-тестер ED Grimes, 2021–2022: деревья скриптам
  недоступны и объектами карты не считаются; проверка пользователя в декабре 2022: в лесной
  зоне 0 объектов карты), а не из документации ED и не из нашей проверки: живая проверка
  OBJ-T32 ещё не сделана. Считайте пустой результат поиска «нет известных объектов», а не
  «нет леса».
* `getDesc().box` объекта карты (есть не у всех) — грубый габаритный прямоугольник, а не форма
  столкновений; нависающая скала и склон под моделью в нём не видны.
* В DCS есть недокументированная таблица `Disposition` (её вызывают скрипты генератора задач,
  которые идут с DCS, и обёртка MOOSE) — поиск «чистых» точек. VEAF измерил на карте Сирия в
  ноябре 2026, что она не видит лесов (0 занятых клеток из 58 081 в лесах полуострова Акамас и
  у FARP Джейхан), а их обходной путь читает файлы карты, чего Sortie делать не может. Sortie
  её не использует, в каталоге её нет.

Что делать вместо этого:

* **Уклон и неровность** — по сетке `ctx.dcs().land().height(..)`: несколько точек вокруг
  каждой будущей машины; разница высот на длине машины даёт уклон, разброс — неровность. Пакет
  из нескольких десятков чтений высоты дешёвый ([пакет](dcs.md#вызов-по-имени)).
* **Известные объекты рядом** — `ctx.search_objects` в радиусе вокруг каждой позиции: здания,
  статики, техника.
* **Проверенные площадки** — зонами сценария: площадки, которые вы сами проверили (в редакторе
  миссий или в игре), и запретные зоны вокруг лесов объявите в `scenario.py` (`sc.zone(..)`:
  круг или четырёхугольник) и выбирайте в Rust: попадание точки в зону
  (`zones::X.contains(точка)`) считается без вызова DCS. Выбранную площадку храните в
  `ctx.state(..)`, чтобы после перезапуска логики спавн шёл туда же.

## Группа из шаблона в точке

`ctx.spawn_group(шаблон)` ставит группу из шаблона сценария: без размещения — там, где её
нарисовал сценарий, со всеми курсами шаблона, с `.from_airbase(..)` — на аэродроме
([спавн](sdk.md#спавн-и-задачи-авиации)). В точку карты группу ставят два метода:

<!-- snippet: sdk-objects-formation -->
```rust
// Наземный шаблон вашего манифеста: зенитная батарея, нарисованная под опорный курс шаблона
// (с шаблоном в scenario.lock.json это `templates::SAM_SITE`).
const SAM_SITE: TemplateRef<MyMission, Ground> = TemplateRef::new("SAM_SITE");

#[sortie::mission(api_rev = 3)] // .at_formation — API ревизии 3
pub async fn sam_site(ctx: Ctx<MyMission>, _start: Start) -> sortie::Result<()> {
    let site = zones::TARGET.center();
    let facing = 140.0_f64.to_radians(); // курс в радианах, по часовой от севера
    // Строй поворачивается целиком вокруг первой машины на (140° − опорный курс шаблона):
    // пусковые под −15° и +15° от опорного курса смотрят на 125° и 155°.
    let battery = ctx
        .spawn_group(SAM_SITE)
        .at_formation(site.alt(m(0)), facing)
        .key("battery-north")
        .await?;
    // .at(..) — как в 0.1.0–0.3.0: все машины смотрят на 140°, строй только переносится.
    let decoy = ctx
        .spawn_group(SAM_SITE)
        .at(site.toward(0.0, m(2_000)).alt(m(0)), facing)
        .key("decoy-north")
        .await?;
    ctx.report().set("battery", battery.name());
    ctx.report().set("decoy", decoy.name());
    ctx.end_session(Outcome::Draw).await
}
```

* `.at(точка, курс)` — поведение 0.1.0–0.3.0, оно не меняется. Первая машина шаблона встаёт в
  `точку`, остальные — со своими смещениями от неё, как в шаблоне: строй переносится, но **не
  поворачивается**, и **все машины смотрят на один `курс`**. Курсы машин из шаблона теряются:
  батарея с пусковыми под −15° и +15° встанет с одинаковыми курсами.
* `.at_formation(точка, курс)` (0.4.0, ревизия API 3) поворачивает строй как одно целое вокруг
  первой машины на угол `курс − опорный курс шаблона`. Смещение каждой машины от первой
  поворачивается на этот угол, и каждая машина смотрит на свой курс из шаблона плюс тот же
  угол, поэтому разница курсов машин остаётся как в шаблоне. Первая машина стоит в `точке`.
* Опорный курс — курс, под который нарисован строй: `Template.heading_rad` манифеста
  (генератор пишет его в каждый шаблон, который строит; наземный шаблон с курсами машин врозь —
  `sc.ground_template(.., heading=90, unit_headings=[-15, 15])`, [генератор](generator.md); в
  своём манифесте задайте его сами).
  Если его нет, опорный — курс первой машины шаблона, и она смотрит ровно на `курс`.
* Курсы — радианы по часовой стрелке от севера, как в DCS; `psi` в таблице DCS движок ставит
  равным `−курс` каждой машины.
* В обоих режимах маршрут шаблона не переносится: у группы одна точка маршрута в `точке`
  (`Off Road` у наземной группы, `Turning Point` на высоте `точка.y` у авиации). Маршрут — потом,
  через `set_task` или `push_task`.
* Логика объявляет `#[sortie::mission(api_rev = 3)]`. С меньшей ревизией `.at_formation` —
  `Error::Revision`, против движка ревизии ниже 3 — `Error::EngineTooOld`, и в DCS ничего не
  уходит. `.at` работает с любым движком.
* Ключ защищает одну команду. Повтор того же `.at_formation` с тем же ключом возвращает ту же
  группу и ничего не ставит. Тот же ключ сначала у `.at`, потом у `.at_formation` (или наоборот)
  — это две разные команды: вторая — `Error::Invalid`, и до DCS она не доходит
  ([ключи](sdk.md#ключи-и-идемпотентность)). Переводя спавн на `.at_formation`, дайте ему новый
  ключ (`battery-north-v2`).
* Элемент `ctx.spawn_batch()` с `.at_formation` ставится так же, а пакет с таким элементом —
  ревизии API 3.
* Что DCS сохраняет курс каждой машины наземной группы после `coalition.addGroup` и не
  разворачивает машины по маршруту из одной точки, видно по записи Tacview клиента; сами мы этого
  не измерили (живая проверка `OBJ-T34`).

## Пакет спавнов

Постоянный сервер начинает с восстановления кампании: сотни групп и статиков. `ctx.spawn_batch()`
собирает их в одну команду с одним ключом: элементы строятся как обычно (`ctx.spawn_group(..)`,
`ctx.spawn_static(..)`), но не ожидаются, а добавляются в пакет.

<!-- snippet: sdk-objects-batch -->
```rust
// Восстановление кампании: одна команда, один ключ; движок проверяет весь пакет сразу.
let mut batch = ctx.spawn_batch();
let cap = batch.add_group(
    ctx.spawn_group(templates::RED_CAP.named("Red CAP 1"))
        .from_airbase(airbases::NALCHIK, StartType::Runway),
);
let farp = batch.add_static(
    ctx.spawn_static("FARP", "USA")
        .named("FARP North")
        .at(zones::TARGET.center(), 0.0)
        .heliport(Heliport::new()),
);
for (name, p) in saved {
    batch = batch.static_object(
        ctx.spawn_static(".Ammunition depot", "USA")
            .named(name.as_str())
            .at(*p, 0.0)
            .on_conflict(OnConflict::Keep),
    );
}
// Ограничитель спавна раздаёт элементы по времени: ответ приходит после последнего.
let out = batch.key("restore-turn-7").await?;
let cap: Group<Air> = out.get(&cap)?; // типизированный результат элемента
let farp: SpawnedStatic = out.get(&farp)?;
for item in out.items.iter().filter(|i| !i.is_ok()) {
    // Ничего не откатывается: у каждого элемента свой результат.
    ctx.report().set(
        item.name.as_str(),
        item.error().map_or("skipped", |e| e.code()),
    );
}
```

* Пакет проверяется целиком до отправки: каждый элемент — проверками своей команды (шаблон,
  имя, таблица типов статиков), имена внутри пакета не повторяются. Один плохой элемент — ошибка
  всей команды с номером элемента, в DCS не уходит ничего. От 1 до 512 элементов. Имя, которое
  уже занято в мире (живая группа, статик) или спавном в полёте, — ошибка только этого элемента
  (`NAME_CONFLICT`), остальные ставятся; с `.stop_on_error()` элементы после него пропускаются.
  Ограничитель спавна пакет делит по очереди с другими спавнами: спавн другой логики не ждёт
  конца пакета.
* Ограничитель спавна (по умолчанию 2 группы и 24 юнита в секунду, пока в сессии есть игрок;
  пока никого нет — ворота разогрева, их ограничивает бюджет моста; статик считается одной
  группой и одним юнитом) раздаёт элементы по кадрам: ответ приходит, когда ответил последний,
  а уже поставленные элементы тем временем в мире и видны игрокам. Каждый элемент сразу
  применяется к миру как своя команда: статик получает `Birth`, задачу новой группе движок
  придерживает, как после `spawn_group`. Срок по умолчанию — срок полосы BULK плюс время,
  которое нужно ограничителю; с 0.4.0 ожидание у ограничителя срок не съедает вовсе, а два
  пакета сразу получают места по очереди.
* Ничего не откатывается. Команда успешна, если пакет запустился, что бы ни сделали элементы:
  `SpawnedBatch::items` — результат каждого по порядку, `out.get(&slot)` — типизированный
  (`Group<K>` или `SpawnedStatic`) либо ошибка, которую вернула бы команда элемента.
* `.stop_on_error()`: элементы идут по одному, первая ошибка останавливает пакет, остальные
  помечены `skipped` (`Error::Rejected`) и в DCS не уходят. Срок пакета тоже останавливает его
  (`skipped` с `Error::Timeout`).
* Один ключ на пакет: повтор с тем же ключом и тем же телом — сохранённый результат, ничего не
  ставится второй раз. Свои `.key`, `.timeout`, `.after` у элементов не действуют. В
  `sortie dev` пакет без `.key(..)` отклоняется.
* Если связь с миссией оборвалась посреди пакета, команда — `Error::Unavailable`. Повтор с тем же
  ключом до полного снимка мира после переподключения отвечает `Error::Unavailable` и называет
  элементы, о которых неизвестно, запустились ли они. После снимка повтор продолжает пакет:
  найденные по имени элементы отмечены `settled` (их Eid — найденный объект), остальные
  ставятся, ни один не ставится дважды.
* Возможность — `caps::SPAWN_BATCH` ([Возможности движка](capabilities.md)). Если владелец
  движка выключил `spawn_static` или `spawn_group`, пакет с таким элементом отклоняется
  (`Error::Rejected`, `Error::capability()` называет операцию элемента).
* Живая проверка OBJ-T31 (300 групп и 100 статиков, время кадра сервера, обрыв связи посреди
  пакета) ещё не проведена; `kept` у статика из пакета всегда `false`.
