# Вопросы и ограничения

## Вопросы

**Нужен ли сервер?** Нет. Sortie работает в одиночной игре, в сетевой игре с хостом-клиентом и
(ещё не проверено) на dedicated server. `sortied` и логика запускаются на той же машине, что и
DCS.

**Можно ли пользоваться редактором миссий?** Собранную миссию можно открыть, посмотреть,
пересохранить и запустить из редактора. Группы, юниты и зоны меняйте в сценарии: правки в
редакторе разойдутся с manifest. Готовую миссию из редактора можно разобрать командой
`sortie-gen adopt` и перенести в сценарий.

**Можно ли писать логику миссии в `.miz`, DO SCRIPT на Lua?** Нет. `.miz`, который собирает
сценарий, — только карта: группы, юниты, статика, зоны, погода, брифинг, начальный запас
складов и bootstrap самого Sortie. Вся игровая логика — что и когда происходит, спавн, задачи,
счёт, меню, метки, изменения запаса — пишется в логике на Rust. Подробнее — в
[Сценарии на Python](generator.md#логика-миссии-и-do-script).

**Работают ли в миссии другие скрипты?** Sortie добавляет в миссию триггер с bootstrap (и, если
у флагов есть начальные значения, триггер, который их ставит) и ничего не удаляет. Сторонний
скрипт, который миссия обязана сохранить, можно добавить DO SCRIPT в хуке `@sc.pydcs`: это не
место для логики миссии, и Sortie такой скрипт не проверяет. Сборка перечисляет каждый такой
DO SCRIPT (и скрипт инициализации, и условие LUA PREDICATE); `Scenario(do_scripts=..)` решает,
предупредить (по умолчанию), отказать (`"deny"`, так делает шаблон) или промолчать (`"allow"`),
см. [Сценарий на Python](generator.md#логика-миссии-и-do-script). Совместная работа с MOOSE,
MIST и подобными библиотеками не проверялась.

**Как обратиться к группе, у которой нет `ident`?** Через мир и события по имени DCS:
`w.group("Имя группы")`, `w.units().in_group("Имя группы")`, `events.in_group("Имя группы")`.
Типизированного символа у такой группы нет.

**Что делать с тем, чего нет в API?** По порядку, и всё это — в логике на Rust:

1. типизированная команда или запрос ([Логика на Rust](sdk.md)); маршрут наземной группы —
   `Task::ground_route(..)` ([пример](sdk.md#задачи-наземных-и-морских-групп));
2. вызов функции DCS из каталога: обёртка вроде `ctx.dcs().land().height(точка)`, а с
   cargo-фичей `dcs-raw` — вызов по пути `ctx.dcs().call(..)` и пакет многих вызовов в одном
   кадре `ctx.dcs().batch()` ([Вызовы DCS](dcs.md));
3. сырая таблица задачи DCS, `group.set_task(Task::raw(..))`, для того, чего нет в
   типизированных задачах: остановка колонны, задачи в точках маршрута, маршрут корабля
   ([пример](sdk.md#задачи-наземных-и-морских-групп)). Её принимает любая группа, а морская —
   только её. Движок проверяет таблицу только на
   безопасность: код Lua (`Script`, `ScriptFile`, строковое условие `condition`), имена файлов
   и числа NaN и бесконечность отклоняются (подробнее — в
   [Эксплуатации](operations.md#проверка-сырых-таблиц));
4. если и этого не хватает, напишите команде Sortie, чего не хватает.

DO SCRIPT в `.miz` в этом списке нет. Статику, погоду и брифинг задаёт хук `@sc.pydcs` в
сценарии.

**Можно ли собирать на Linux?** Логику и сценарий — да. Рантайм работает только на Windows, рядом
с DCS. API движка по умолчанию слушает только `127.0.0.1`, и так его и оставляйте: API управляет
сервером. Поэтому логику запускайте на той же машине, что и `sortied`.

**Под какой лицензией SDK?** Крейты SDK, `sortie-gen`, шаблон и примеры — MIT OR Apache-2.0, на
ваш выбор. Рантайм (`sortied`, `sortie`, мост) распространяется под своей лицензией: файл
`LICENSE` в архиве рантайма.

## Ограничения версии 0.4.0

**Проверка в игре.** Проверены одиночная игра и сетевая игра с хостом-клиентом в DCS 2.9.31.
Dedicated server, `restart`, `launch` и проверка типов в живой игре ещё не проверялись.

**Ещё нет:**

* тестов без DCS (`#[sortie::test]`, FakeDcs): FakeDcs содержит движок, и в публичный SDK она
  пока не входит;
* горячей замены логики (`--standby`) и команд `sortie dev`, `sortie trace`, `sortie record`;
* цикла кампании: `sortie-gen worker` выходит с кодом 2, автоматической сборки следующего хода
  нет;
* восстановления сессии после перезапуска движка (`Start::Resumed`);
* перезапуска DCS после краша и зависания (это может делать DCSServerBot);
* замеров производительности DCS (`sortie probe`).

Вызовы того, чего ещё нет, возвращают ошибку «... lands in Mx» или код выхода 2, а не падают.

**Сценарий.** Размещённые группы — наземные (`ground_group`). Самолёты и вертолёты — шаблоны для
спавна и слоты игроков. Корабли и прочее — через хук `@sc.pydcs`, без символов для логики.

**Задачи.** Типизированные задачи `Task::cap`, `orbit`, `rtb` — только для самолётов и
вертолётов, маршрут `Task::ground_route` (ревизия API 3) — только для наземных групп. Морская
группа принимает только сырую таблицу задачи DCS (`Task::raw`). Остановки колонны и задач в
точках маршрута в типизированном виде пока нет: это тоже `Task::raw`.

**Движок:**

* не больше 2 групп и 24 юнитов спавна в секунду, пока в сессии есть игрок; пока никого нет
  (сервер только загрузил миссию), спавн ограничивает бюджет моста в DCS (20–50 спавнов в
  секунду в зависимости от FPS); ожидание очереди спавна не съедает срок команды (0.4.0);
* задачу только что созданной группе движок отдаёт не раньше чем через 2 кадра и 0,5 с;
* логику, которая перестала читать поток (например, остановлена в отладчике), движок отключает
  после 4096 непрочитанных сообщений; перезапуск подключает её снова;
* подписчик событий, отставший больше чем на 1024 события, пропускает самые старые.
